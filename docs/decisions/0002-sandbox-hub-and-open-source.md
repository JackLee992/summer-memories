# ADR 0002：沙盒形态与开源复用策略 —— 海岛枢纽半沙盒 + 组件级开源复用

- 状态：**已采纳（方向锁定）**
- 日期：2026-09-20
- 决策者：项目所有者（明确要求"做成沙盒类、可基于开源游戏减少工作量"）；形态与复用粒度由技术侧收敛
- 关联：ADR-0001（Unity 6 LTS）、GDD.md、architecture.md、licensing-and-copyright.md、roadmap.md

## 背景

所有者希望游戏具备沙盒体验，并优先复用开源成果以减少工作量。与此同时，已落地的 v0.1 MVP
确立了三大核心：**时间回溯（回潮）＋网格策略战棋＋电影式 ADV**，主题为中国神话叙事
（人性 / 生死 / 爱情），对标《黑神话：悟空》的"神话为余烬、原创主角"方法论。

需要回答两个问题：

1. 做到什么粒度的"沙盒"，既给玩家自由探索感，又不稀释悬疑时间循环核心、不拖垮小团队产能？
2. 哪些开源资产能**合法用于未来商业产品**、并真正减少工作量？

调研了三类开源基座（叙事对话、2D 俯视角/农场生活模拟、战棋框架），结论如下。

### 调研结论（2026-09）

| 类别 | 候选 | 许可证 / 适配 | 结论 |
|---|---|---|---|
| 叙事 / 对话 | **Yarn Spinner for Unity** | **MIT**，免费可商用，Unity 官方包形态；Night in the Woods、A Short Hike、Lost in Random 等已验证；2.x/3.x 持续维护 | **采用**：承担沙盒层 NPC 自由对话与支线分支 |
| 2D 俯视角 / 地图 | Unity 内置 **2D Tilemap / 2D Animation / Cinemachine** | 引擎能力，无额外许可；Unity 官方 GitHub 示例多为 MIT/X11（以各仓库 LICENSE 为准） | **采用**：作为探索层地基 |
| 完整农场 / 生活模拟开源游戏 | 网上多为 Udemy/Sunny Valley 等**付费课程完整工程**、itch 学生小品、Stardew modding 工程 | 课程工程许可通常仅限学习、**禁止商用再分发**；itch 小品许可证不明；StardewCommunity 工程基于 MonoGame/XNA（非 Unity）且是 mod 非独立基座 | **不 fork**：无"许可证干净 + Unity 6 适配 + 活跃维护"三者兼备的完整候选 |
| 战棋 / SRPG 框架 | Asset Store（Turn Based Strategy Framework、Tactics Toolkit 等，付费 EULA）、itch Tactics RPG Framework、各类 GitHub 教程 | 商业 EULA 或许可证/维护度参差；与自研回溯机制耦合成本高 | **不换**：自研战棋已完成并通过 headless 束搜索验证（首战 5 回合可胜），替换为负收益 |
| 主线 ADV / 回潮 / TIPS / 存档 | 本仓库自研 | MIT（自有） | **保留**：与回潮机制深度耦合，继续承担电影式主线 |

> 关键判断：**不存在**一个能直接当作"夏日回忆沙盒层"的完整开源游戏。盲目 fork 完整游戏会同时背上
> 技术债（别人的架构/数据格式）与版权风险（课程代码、GPL、CC-BY-NC）。真正省工作量的方式是
> "成熟组件级开源（对话/2D 能力）＋自研薄胶水层与玩法规则"。

## 决策

### 1. 沙盒形态：海岛枢纽半沙盒（Hub-World），不做全开放生活/经营模拟

采用**章节制枢纽半沙盒**：每一章提供一张可自由游走的渔村/海岛地图（2D 俯视角 Tilemap），
玩家在其中自由移动、与有日程的 NPC 交谈、收集情报与道具、建立羁绊，并从多个入口触发
**电影式 ADV** 与**网格战棋**；死亡或关键节点触发**回潮**，进入下一周目。

- **保留（沙盒感来源）**：自由探索、NPC 日程生态、多线索/多解法、道具与情报收集、
  分支对话、可选区域与隐藏事件、玩家自定的时间安排。
- **不做（产能黑洞）**：开放世界、大规模建造、完整农场经营（种植/畜牧/季节产出闭环）、
  流水线生产。种田/钓鱼/赶海最多作为**轻量氛围小游戏与道具来源**，不进入核心循环。
- **回潮规则（与核心强绑定）**：跨周目**继承**——TIPS 情报、已揭示真相、玩家对规律的认知、
  已激活的锚点/捷径、羁绊等级；**重置**——世界状态、NPC 位置、消耗品、当日事件。
  这一时间循环结构对标《塞尔达传说：梅祖拉的假面》的三日循环、《夏日重现》的潮循环、
  《死亡循环》的"信息永久、物质重置"，让沙盒探索直接服务于"回溯"主题。

理由：枢纽半沙盒以"一张地图/章"的可控产能，提供 80% 的自由探索体验；自由探索产出的情报与
道具反过来给战棋更多策略选项、给 ADV 更多分支，三大系统互相放大而非并列堆叠。

### 2. 开源复用：只做组件级白名单复用，禁止 fork 整游戏与传染性许可

- **白名单（可直接引入，保留版权声明即可闭源商用）**：MIT / Apache-2.0 / BSD；
  Unity 引擎内置能力与 Unity 官方 MIT 示例。
- **灰名单（需法务/所有者确认后逐项决定）**：Unity Companion License（UCL，只能在 Unity 项目内
  使用、不得将其素材/代码单独转售——做成游戏一般可行）；Asset Store / itch 的商业 EULA 资产。
- **黑名单（不得进入工程）**：GPL / LGPL / AGPL（传染性或动态链接义务，威胁闭源商业化）、
  CC-BY-NC / NC-ND（禁商业衍生）、付费课程完整工程代码、许可证不明的 GitHub/itch 工程与素材。
- 所有第三方依赖必须登记到 `docs/licensing-and-copyright.md` 的"第三方组件清单"
  （名称 / 版本 / 来源 URL / 许可证 / 用途 / 引入日期），并在发行包内附带 THIRD-PARTY-NOTICES。
- **首个计划引入的组件：Yarn Spinner for Unity（MIT）**，仅用于沙盒层 NPC 对话与支线；
  主线电影式 ADV 仍由自研 AdvDirector 承担（它与回潮、TIPS、loopreset 深度耦合）。
  两者通过统一接口收敛：对话产出的"标志 / 解锁 TIPS / 给予道具 / 触发事件"汇入同一个世界状态。

### 3. 工程接缝（在现有六程序集上增量，不推翻）

- 新增程序集 **`SummerMemories.Explore`**（沙盒探索层，纯逻辑可离线编译）：
  - `WorldModel`：地图、场景切换点、交互点、可拾取物（数据驱动 JSON，放 `Resources/World/`）。
  - `NpcSchedule`：按"周目内日期 + 时段 + 天气"驱动 NPC 位置与可对话内容（数据表，不写死）。
  - `ExploreDirector`：俯视角移动/交互状态机，输出"进入 ADV / 进入战斗 / 解锁 TIPS /
    给予道具 / 切换场景"等意图，交由 App 层调度。
  - 回潮时由 App 层按"继承/重置"规则重建世界状态。
- `GameDirector` 状态机扩展为：
  `Title → Explore（枢纽） ⇄ ADV / Battle → LoopReset（回潮教学/结算）→ Explore（新周目）→ Timeline`。
  v0.1 的线性 `prologue → loop_teaching → battle_01` 作为**第一章的脚本化特例**保留并可直接通关。
- `SaveSlot` 扩展：世界状态、场景锚点、收集物/道具、羁绊、NPC 日程推进（继续用 List 结构，
  兼容 JsonUtility；不引入 Dictionary 序列化）。
- 跨周目继承继续以已就绪的 **TIPS 系统**为骨干，新增"道具/锚点/羁绊"白名单继承。
- 视图层：探索层用 Tilemap + 顶视角色控制器（自研薄控制器，移动/碰撞参考 Unity 官方 2D 示例写法，
  不拷贝 UCL 素材）；UI 仍统一走 `UIFactory`/Palette 风格。

## v0.2 范围（沙盒层，Android 优先）

1. 引入 Yarn Spinner（MIT）并跑通一个 NPC 对话样例；建立 THIRD-PARTY-NOTICES 与组件登记。
2. 一张枢纽地图（渔村码头/坡道/海堤，复用现有 bg_dock/bg_town/bg_night 美术基调）：
   Tilemap 碰撞、顶视角色移动、场景切换点、3–5 个交互点。
3. 2–3 名 NPC 的日程表（早/午/晚位置变化）与自由对话（Yarn），对话可解锁 TIPS / 给予道具。
4. 世界状态与回潮继承/重置规则落地，存档扩展并通过杀进程续档测试。
5. 把 v0.1 的序章/教学/首战接入枢纽：从探索层入口触发，胜利后回到枢纽（而非直接结束）。
6. 离线编译检查与（license 就绪后）真机走查：探索→对话→ADV→战斗→回潮→继承验证闭环。

非目标（v0.2 不做）：经营闭环、战斗技能大扩充、多章内容、iOS/Switch 出包、Live2D/配音。

## 已知后果与约束

- Yarn Spinner 引入会增加一个第三方运行时依赖与版本锁定；升级需回归沙盒对话流程。
- 半沙盒对地图/关卡/内容产能提出新要求；务必坚持"一章一图、数据驱动、氛围小游戏不做系统"的范围纪律。
- 课程/开源工程的**设计思路**可学习、可重写，但代码与美术不拷贝；任何外部素材进入仓库前先验许可证。
- AI 生成图仍仅作原型占位，商业化前全部原创重绘（沿用既有版权红线）。
