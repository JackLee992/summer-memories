# Demo 实查：哪些保留，哪些改造

日期：2026-09-20。目标方向已由所有者确定为《夏日重现》人物背景的 PC 小队策略冒险动作原型，见 [ADR-0003](decisions/0003-pc-action-adventure.md)。

## 1. 结论

这个工程值得继续使用：原创叙事有明确主题，Unity 工程、内容组织与旧战棋逻辑已有可验证基础，3D 动作原型也已经能运行。它目前处于**叙事 Demo + 动作白盒**阶段。距品质切片最大的缺口是角色动画、战斗设计、探索内容、3D 美术、声音及整合验证。

旧神话人物与剧情是历史基线；新原型保留慎平、潮等原作人物。优先投资「为什么需要队伍配合、玩家如何识别影子、回溯后的情报怎样改变行动」。单纯提高贴图分辨率、加泛光或继续堆技能，不能解决这些缺口。

- 内容基线：5 份 Resources JSON、10 张 PNG 原型图、12 个 Action3D C# 文件。未找到 FBX、动画剪辑、Animator Controller 或 wav/ogg/mp3 音频资产。

- `bash tools/battle_sim/run_sim.sh 6000.0.83f1`：旧战棋首战找到并复盘 5 回合胜利路径，剩余桃橛 2。仅证明该战斗逻辑可胜，不证明 UI、失败分支或 3D 已全部回归。

- 检查期间最新 `Builds/build-mac.log` 显示 Unity 6000.0.83f1 的 Mac 构建 Succeeded，约 242 MB；通过原生应用自动化打开/检查了该包。
- Unity 游戏窗口只暴露窗口级辅助功能树，实际玩法依靠截图核验：看到海堤、玩家、三只夜叉；键盘技能输入后看到了火眼激活文案、武器姿态变化；随后看到回潮额度减少、耗尽后的失败画面。按回车后观察到重新战斗画面，但位置恢复正确性仍需独立回归。

## 4. 已有具体问题与优化优先级

下列引用为审计时文件位置。P0 阻碍可靠闭环，P1 直接损害动作体验或内容正确性，P2 为品质建设。代码可确认的问题与待复现实机风险分别标明。

### P0：先确保回潮和进度可信

1. **动作版回潮只是本场重置，尚未接入叙事持久化。** `Action3D/Rewind/Rewind3D.cs:33` 只捕获开局位置、朝向、最大生命和次数；`Boot/Game3DDirector.cs:149` 死亡消耗本场额度，未调用 SaveSystem / TipsSystem。与 GDD 的外层情报继承、记忆代价并非同一系统。修复方向：App 统一调度，明确战斗快照、检查点和跨轮情报三种状态的生命周期。

2. **回潮时动作协程和冷却没有完整清场（代码确认，竞态需 Play 模式复现）。** `Player/PlayerController3D.cs:395` 的 ResetState 只清 `_action` 引用，没停止正在运行的协程，也没重置 EyeCdUntil、桃橛/闪避冷却、垂直速度与受击基线；导演器只是禁用组件。应覆盖「重击起手时死亡」「闪避尾帧死亡」「回潮后立即施法」「连续重试」；用统一的退出/重置方法停止动作，恢复完整战斗状态。

3. **复活时先开启 CharacterController 再写位置（位置复原待验证）。** `Combat/Combatant3D.cs:184` 同时没有停止倒地/闪色协程。应在禁用碰撞控制器期间恢复 Transform，清空旧视觉和运动任务，再一致启用。不能只以血条回满判断快照恢复成功。

4. **旧版「继续」不恢复对白与选择。** `App/GameDirector.cs:61` 对未通关存档直接 StartBattle；`Core/Save/SaveSlot.cs:29` 虽有脚本/指令字段，却未从播放进度写入；`ADV/AdvView.cs:47` 接到 flag 事件只 Refresh，没有写入 SaveSlot。修复方向：统一剧情状态接口；存到选项前、选项后和回潮前分别重进，核对场景、指令及标志。

5. **存档隔离失败会被吞掉，写入非原子。** `Core/Save/SaveSystem.cs:51` 的 Move 失败被忽略，随后仍返回 null；`:26` 直接覆盖 JSON。需要保留隔离失败的明确错误状态，避免上层按「无存档」继续覆盖；增加同目录临时文件写入、替换、版本与字段校验。保留既有固定路径及 `.broken-<ticks>` 规则。

### P1：动作体验与可读性

| 发现 | 证据 | 改进和验证 |
|---|---|---|
| 奔跑无法真正耗尽体力 | `PlayerController3D.cs:97,125`，Free 每秒回 30，奔跑只扣 14 | 消耗和回复互斥，并有回复延迟；从半管体力持续跑到耗尽，再停跑恢复 |
| 红光预警实际无效 | `Combatant3D.cs:174` 仅改 `_EmissionColor`；`Resources/Shaders/SMUnlit.shader:7` 只有 `_Color` | 先保证白盒也能看懂前摇，再制作正式特效；不能仅依赖颜色区分攻击 |
| 起手/出手一直朝玩家追踪 | `Combat/Enemy3D.cs:83` 在所有状态都朝玩家旋转 | 在招式指定时间固定攻击方向；检验侧闪后是否仍被无预兆转向命中 |
| 桃橛只是暂停敌人状态，没有清除已蓄力招式 | `Enemy3D.cs:73` 眩晕时 return，原 `_st/_t` 保留 | 明确「打断」与「暂停」；打断型眩晕结束后应重新给足前摇 |
| 击杀后可能仍锁着尸体 | `PlayerController3D.cs:388` 有 ClearLockIf，但正常击杀路径未调用；只在 Rewind.Restore 调用 | 死亡/越界/遮挡时清锁，切换目标与镜头共同验收 |
| 镜头灵敏度有帧率依赖风险 | `Input3D.Look()` 用 Mouse X/Y 位移，`CameraRig3D.cs:65` 再乘 deltaTime | 区分鼠标增量与摇杆速率；30/60/120 fps 下以相同设备位移验证角度 |
| 触屏输入边沿可能被提前清掉 | `Game3DDirector.cs:120` 在 Update 清 EndFrame，各组件没有规定更新顺序 | 一处采样、每帧稳定读取、LateUpdate 或帧号失效；这项是风险，尚未做触屏复现 |
| 剧情、关卡和 HUD 文案硬编码 | `Game3DDirector.cs:60` 敌人数值数组；`UI/Hud3D.cs:79` 开场剧情直接放 C# | 迁到既有 Battles / Story / Localization，校验 id、时间参数与引用 |
| 双启动相互清理 | `Boot/Game3DBootstrap.cs:26` 按名字销毁 GameDirector，后者 Awake 已创建旧 UI | App 在创建前选模式，避免跨层查找/销毁；分别验证旧 Demo 和动作入口 |
| 场景横条比例异常 | `World/WorldBuilder3D.cs:90` 把石缝挂在已缩放为 10×1×84 的路面下，却再次传入世界尺度；实机可见横条延伸到海上 | 改用未缩放的场景根节点，或换算为父局部单位；检查世界尺寸与碰撞 |

### 旧版剧情审计与新模式迁移注意

- `prologue.json:18` 直接解锁 `tip_puti`，该异闻标题是「七爷·菩提」，时间线确实会列出已解锁标题；这与设定集「不点破、不喊仙名」冲突。迁移时需把玩家可见标题改为当期称呼。
- `tip_liuer` 含有把主角能力与终章身份直接关联的文字。目前未看到序章解锁该 id，不能声称已在游戏中泄露；新增完整图鉴时必须加揭示门槛，不能把整个目录默认公开。
- 火眼当前只是 3.5 秒双倍伤害窗口（`PlayerController3D.cs:292,355`），回潮只是重打，尚未形成「掌握情报改变行动」的独特循环。应优先制作一个可通过观察破解的招式/路径，验证异闻在第二次尝试中确实有用。
- 正式动作切片应重写「一回合」「落子之前」等旧教学用语；旧战棋 JSON 留在旧入口，避免把它们作为动作版教学。

## 5. 质量参考与落地顺序

| 对标体验 | 当前小队原型落点 | 验收证据 |
|---|---|---|
| 动作重量与镜头 | 慎平和潮各自的动作逻辑，头发能力与队友配合 | 起手/命中/收招可读，切换不产生状态丢失 |
| 空间与细节 | 可探索的海岛与可信的调查物件 | 影子、头发、贝壳可调查且影响后续决策 |
| 能力与策略 | 扫描物品，切换潮并变成已有形态，部署队友 | 变形影响碰撞/侦测，协作比单人硬打更有效 |
| 叙事与回溯 | 保留原作人物与核心情境，游戏任务和对白新写 | 失败后有新认识，第二次尝试能改变结果 |

执行顺序与验收写入 [路线图](roadmap.md)。下一轮优先交付 S0 基础可靠性、S1 两人战斗与能力，再做 S2 调查和回溯；AI 美术、程序音频、影视动作参考作为并行的制作样板。当前不提供缺乏团队和目标机依据的全作工期、费用或完成百分比。

本轮新增的内容草案与声音见 [小队方案](st-squad-demo.md)。这些不是已接入的新角色、新能力或新关卡。
