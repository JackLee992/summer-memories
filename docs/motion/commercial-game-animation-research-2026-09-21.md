# 商业 2D 动作游戏动画管线调研

日期：2026-09-21。范围：一手案例与可验收标准；不恢复开发，不安装软件、不生成素材、不构建。本文的建议门槛不是现有原型已达到的结论。

## 结论

从程序剪纸人到商业观感，缺的主要不是“更多中间帧”，而是**确定的角色造型、专业关键姿势、动作时序、可编辑的制作资产，以及受击与操作规则的联调**。部件保持长度、头发有延迟，只解决连续性中的一部分；错误的重心、平直的速度、虚假的握持和没有承重的接触，会在平滑后变得更明显。

小团队应先验收“一名角色、一种武器、一套有起止和命中分支的动作”，再增加人数、技能与关卡。先用实际游戏机位看动作，不能只在放大预览、慢放或宣传镜头里成立。AI 视频可以帮助讨论表演和找姿势；视频插帧不能提供可控的取消窗口、稳定握点、碰撞语义或可修改骨架。

## 必须分开评估的三层质量

| 层 | 要解决的问题 | 独立验收办法 |
|---|---|---|
| 画面 | 造型、线条、颜色、材质、角色与背景的辨识度 | 单帧和游戏实际显示大小审查；不可依靠运动模糊遮掩解剖或遮挡错误 |
| 动画 | 姿势、重心、弧线、快慢、停顿、接触、跟随与回收 | 关掉特效、音效、镜头震动，正常速度看；再逐帧查握持与脚底 |
| 操作反馈 | 输入何时响应、攻击何时有效、是否可取消、命中如何反馈 | 在运行时比较命中/挥空、连按/单按、转身/受击等分支；渲染视频不能证明这层合格 |

三层有关联，但不能互相替代。漂亮立绘做刚体摆动，仍可能像剪纸；流畅动画被冗长不可取消后摇锁住，仍可能不好操作；强烈震屏和命中闪光也不能修正武器轨迹与接触点错位。

## 核实的一手案例（两例）

### Hollow Knight：传统手绘配合简单运行时表达

Unity 官方案例 [S1] 明确记录：团队在 Photoshop 制作手绘画面与传统动画，保存为 PNG；使用少量简单着色器，以柔和透明形状处理照明，并在 3D 环境中分层放置 2D 资产。文章也说明他们使用 Unity 现有 2D 工具和第三方工具，将精力集中在美术。

可借鉴的是**限定视觉语言并投入高质量动画设计**，不是“PNG 技术简单，所以美术便宜”。来源没有给出各动作的人工耗时、取消窗口或命中停顿数值，本文不替其补写。它也不证明换成手绘后无需动画师。

适合本项目借鉴：有辨识度的剪影、少量清晰关键姿势、角色与环境分层、动画与特效分开制作。不能据此直接照搬它的角色比例、动作造型或素材。

### Unruly Heroes：2D 骨骼之外，使用网格塑造姿势

Spine 官方 Showcase [S2] 收录 Magic Design Studios 的直接评价：Spine Mesh 让设计呈现可信的 3D 观感，也能把关键姿势做 smear 处理，形成有张力的动画。该材料是工具官网上的开发者引述，能证明使用方式；不是完整制作复盘，也不能证明该游戏所有动画只用一种工具。

Spine 官方网格文档 [S3] 进一步解释：网格可以弯曲图片，配合权重随骨骼变形；顶点拓扑决定变形效果。网格的 deform keys 只存顶点位置，插值沿直线进行。因此“给一张图绑骨骼并补帧”不自动等于可信转体、透视或漂亮的运动弧线。文档建议主要使用权重，避免大量 deform keys；本项目不能把逐帧搬顶点当成默认量产方式。

适合本项目借鉴：肢体与躯干的变形设计、重要瞬间的替换图或特殊姿势、头发与衣物的跟随。对大幅转身、手掌翻面、双手握锤、面部角度变化，仍需要作者准备素材和调整遮挡。

未将 Dead Cells 或 Skullgirls 列为已核实案例：本次 Dead Cells 相关 Game Developer/GDC 页面访问返回 403，未取得正文；不凭熟悉的行业说法补写其具体制作步骤。

## 三条制作路线的实际权衡

下表是面向本项目的工程判断，不是案例方公布的成本数据。

| 路线 | 最强项 | 不能自动解决的部分 | 合适的验收样片 |
|---|---|---|---|
| 手绘逐帧 | 极端姿势、夸张透视、smear 和轮廓控制 | 每个新视角与动作仍需绘制；角色一致性、修形和上色需要工序 | 原画关键姿势 → 粗线测试 → 修形上色 → 游戏尺寸播放 |
| 2D 骨骼 + 网格 + 替换图 | 保持角色一致，复用待机/行走/换装，方便迭代节奏 | 不能从单张正面图推导正确侧背面；大幅转体和双手道具交互易显得扁平 | 同一角色的普通循环与高难度挥击均合格，不能只演示呼吸摆动 |
| 固定机位 3D 离线渲染 + 2D 修绘 | 体积、关节、道具尺寸和多段动作共享一套资产 | 建模、拓扑、绑定、权重、握持、动作修正、渲染风格与二维修形仍需完成 | 同一模型在最终正交机位完成挥击并导出一致 pivot 的透明序列 |

固定机位 3D 是资产生产支架，最终仍可在 Unity 6 横版 2D 中播放精灵，不要求更换引擎或把玩法改回自由 3D。若模型只在转台中好看，最终侧面中脸、手、锤头重叠，则生产优势不存在。离线渲染会把结果固化为帧；运行时想改握点、装备或朝向，可能需要重渲染，不能把离线骨架的灵活性误算成精灵的运行时能力。

建议保留现有“3D 支架候选”方向，但不要立即扩充工具链。对同一段挥锤，用同一机位、尺寸与验收表比较可编辑资产和实际返修步骤。若只有骨骼稳定、成片仍像木偶，不能判定路线成功。

## 攻击动画必须附带动作契约

以下是建议的动作设计要求，并非上述商业游戏的实测参数。不给所有武器规定统一帧数：角色体型、攻击范围、敌人威胁和输入方式都会改变合适的时长。

| 阶段 | 动画要求 | 玩法契约 |
|---|---|---|
| 预备 anticipation | 先传达攻击方向与力量来源；身体、手、武器关系清楚 | 输入接受时刻、前摇长度、朝向是否锁定、能否撤回 |
| 生效 active | 武器快速沿有目的的弧线穿过目标区域；必要时用作者设计的 smear | 攻击判定起止、轨迹、每目标命中次数、命中条件 |
| 回收 recovery | 动量有去处；重心恢复，能接回待机或下一动作 | 后摇长度、移动恢复点、连段/闪避/切人取消窗口及优先级 |

动画预备动作并不意味着把玩家所有操作都延迟到蓄力完才反馈；接收输入后应有可读的即时表现。取消窗口属于玩法规则，不能仅靠动画看似衔接推断。至少要记录“何时接受输入、提前输入是否缓存、何时执行、命中与挥空是否不同”。回溯和切人还需确定：取消的是哪个角色的哪个动作、攻击判定是否已结算、道具/头发状态如何归位。

**接触与命中停顿应分开：**握点和脚底接触是几何/动画约束；hitstop 是命中确认后短暂停住指定对象或系统的反馈机制。挥空不能无条件播放与命中相同的硬停顿。命中时要明确冻结攻击者、受击者、粒子、镜头、输入缓存中的哪些部分，以及恢复后是否重复触发判定。对回溯玩法，还需声明停顿使用哪套时间基准。

命中反馈包至少包括：受击姿势或击退、接触点特效、声音、必要的短暂颜色/亮度变化；镜头震动是可选项。先在关闭这些增强效果时检查动作，再开启检查同步。不要用全屏闪光掩盖碰撞对不上。

Unity 6 官方过渡文档 [S4] 支持基于条件、Exit Time、过渡时长和中断来源控制状态切换。它说明了可用机制，但这些参数不会自动建立战斗取消规则，也不保证碰撞时序正确。像素/逐帧动作不应默认长时间交叉淡化；骨骼动画也要检查混合期间是否丢失关键轮廓、脚滑或武器穿身。

## 小团队最低可验收资产包

这是“一名持锤角色的小型质量验证包”，不是全游戏资产数量估算。不设置未经实测的工期或价格。

1. **造型基准**：最终游戏视角的角色标准图、武器比例、手部握点、角色显示尺寸与地面基线。若允许镜像，明确不对称服装/武器是否能镜像。
2. **可编辑源资产**：分层原画与逐帧源文件，或完整 2D 绑定工程，或完整模型/绑定/材质/动画与渲染设置；仅一个 MP4/GIF 不算交付。
3. **基础运动**：待机、移动循环及停止/回待机的可用衔接。跳跃、落地仅在验证场景包含跳跃时加入；不先扩大动作库。
4. **一个完整攻击**：预备、挥击、回收均有可审查关键姿势；具备挥空与命中表现；从待机和移动进入攻击均能成立。
5. **目标反馈**：一个可读的受击动作和接触点效果、音效，以及是否击退的明确规则。目标可以保持简单，但不能用攻击者独演代替接触验证。
6. **时序表**：每段持续时间、图像采样率、攻击生效区间、命中事件、取消/缓存窗口、朝向与位移规则、音画触发点。图像帧率不等于模拟更新率，两者分别记录。
7. **导出约定**：透明底、画布/裁切规则、一致 pivot、像素密度、命名、图集与过滤建议；说明左右朝向、边缘光晕和透明边缘的处理。
8. **验收证据**：正常速度、最终尺寸的循环与命中/挥空对照；关闭特效的版本；关键接触帧与问题清单；后续获准开发后，再补运行时输入与判定验证。当前不启动该开发步骤。

## 质量闸门与失败判据

| 闸门 | 通过条件 | 应退回的典型问题 |
|---|---|---|
| 关键姿势 | 不靠特效即可读懂发力、攻击方向、接触与收势 | 姿势都是同一立绘的旋转；身体未参与发力 |
| 正常速度线测 | 有明确快慢和节奏，重量与武器尺度匹配 | 匀速摆臂；只增加帧数；脚步与重心无关联 |
| 接触审查 | 支撑脚可信；两手握点稳定；锤柄长度与遮挡连续 | 手穿柄、手滑、锤子变长、脚无意滑动 |
| 最终画面 | 游戏尺寸下轮廓清楚；清线、色彩、透明边缘一致 | 只有放大静帧好看；角色与背景融在一起 |
| 操作联调（未来） | 命中/挥空有区别；输入、取消、判定和反馈一致 | 看起来已打中却无判定；后摇吃输入；取消后仍伤害 |
| 可维护性 | 能定位并修改一处握点/时序，稳定重新导出 | 只能重新生成整段视频；每改一帧人物都漂移 |

现有 overlap 实验应保留为“运动连续性研究”，不能用作商业视觉质量基准。下一次若获准制作，优先请有角色动作经验的作者把**少量关键姿势和时序**做到目标水平，再决定手绘、2D 骨骼还是 3D 支架承担中间过程。商业化标准需要真实样片审查，不能由工具名称或生成速度推断。
