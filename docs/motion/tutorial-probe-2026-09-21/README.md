## 看了哪些教程，实际做了哪些

1. **Krita 官方动画文字教程**：已读取关键姿势、复制帧、停留格、洋葱皮和接触点的操作方法；在本次练习中采用“先极端姿势和时序，再中间段”的组织方法。没有声称本轮安装或操作过Krita。
2. **MoMask / KeeMap 官方文字步骤**：已读BVH导入、检查姿势、保存工程，再考虑重定向的流程。本轮完成第一段：直接导入自生BVH并验证可编辑性。KeeMap只声明测试Blender3.3.1，本机5.2，因此没有安装它或复制许可未明确的示例角色。
3. **Blender已安装的BVH导入器与IK API**：实际启用 `io_anim_bvh`，导入后建立2骨IK、pole target、禁拉伸与脚方向约束。IK参数也与[官方源码](https://github.com/blender/blender/blob/main/source/blender/makesrna/intern/rna_constraint.cc)核对。部分在线手册403，未冒充已阅读。
4. Alan Becker 的12原则视频与KeeMap作者视频只核实标题、作者和入口，未观看/转录；因此不把本轮具体动作说成逐步复刻其视频。OpenToonz hooks教程已读，列为后续二维替换画练习，本次未执行。

本轮场景通过自行编写的Blender Python API脚本制作；不是鼠标手绘、真人动捕或视频教程自动复现。Computer Use用于最终对照页检查。

## 实际在线生成了两次

使用[MoMask官方所链HF演示](https://huggingface.co/spaces/MeYourHint/MoMask)，只提交通用英文动作描述，没有上传角色图、工程或身份信息。

| 次数 | 提示意图 | 请求长度 | 返回与文件 | 观察结果 |
|---|---|---|---|---|
| 1 | 双手持重锤，过肩举起，下击一次，回到站姿 | 3秒 | 60帧、20fps BVH/MP4；本地请求返回18.03秒，服务自报16.42秒 | 更像抬手与从蹲姿站起，缺少完整下击/收回，不合格 |
| 2 | 双手过头举起，重斧向下劈木头，简化语义 | 4秒 | 80帧、20fps BVH/MP4；本地请求返回9.72秒，服务自报8.56秒 | 手臂抬举与伸展变化，仍没有可接受的单次挥重物，不合格 |

这是两次具体输入的结果，不能外推MoMask所有动作都无用，也不能从一次返回时间推断未来速度或本机性能。演示未提供可控制seed，本次不可承诺重新请求逐帧相同。

请求、原响应和下载哈希保存在 `request*.json`、`response*.json`、`downloads*.json`。`momask_raw.*`和`momask_second.*`是下载的原始文件。演示共用BVH缓存路径，可能被后续用户覆盖；第二次脚本在成功响应后立即下载，第一份也已保留本地并核对60帧与预览动作。唯一MP4路径及哈希保留用于溯源，公共演示不提供原子化BVH归属保证。

## 为什么没有继续抽结果

按教程先查动作意图，两个输出都没有通过单次挥击要求。继续给它绑定精细日鹤，只会把同样的动作问题包装得更漂亮。本轮停止模型重试，改用同一骨架进行关键姿势练习。

## Blender中实际完成的练习

1. 直接导入第一份BVH，设20fps、1–60帧，保留原动画 `MoMask_first_result_unedited_60f`。
2. 用自行建立的中性几何人偶显示原动作，便于观察膝、肘、躯干。不是第三方成品角色，也没有手指、面部或服装细节。
3. 复制骨架比例，**清除副本原动作并重新制作**；副本名 `B_Authored_pose_to_pose`。这不是少量自动清理，也不是声称把模型输出修好了。
4. 在第1、7、15、21、25、28、31、33、38、44、52、57、60帧布置13个关键时点：包含停留重复姿势，不等于13张独立原画。先扛肩，再压低/举起，加速挥下，短停、卸力、回肩。
5. 上身有髋/脊柱旋转。两臂用2骨IK，禁伸长，pole target控制肘部方向；脚踝位置由IK固定，脚部世界旋转另锁定。
6. 锤子独立刚体；两手目标是锤子控制器的子级，沿柄轴相隔0.22米。这样武器旋转时握点保持刚性，不在不同控制器之间做出错的线性偏移。此尺度是本练习采用的Blender单位设置，不是人体实测尺寸。
7. 快速击出段使用线性曲线，其他段使用自动夹紧Bezier；加入中间姿势，避免旋转只靠两端猜路径。3秒是展示练习，不是已验证的游戏攻击时长。
8. 同一正交机位渲染两版，保存透明度无关的中性背景MP4/GIF和原生`.blend`。没有自动生成商业美术，也没有引入Unity运行时。

原始动作没有道具，因此A栏不添加一把假装正确握住的锤子；B栏的道具和动作都是新增的。A/B是过程结果对照，不是证明某单一算法提升质量的严格消融。

## 验证证据

- Blender 5.2.0 LTS，本机实际运行。BVH导入得到22骨骼、20fps、60帧；末端零长节点由官方导入器补可显示骨长，这不表示模型提供了手指或完整头部结构。
- 原始左右腕间距范围约0.131–0.361米，没有保持本练习所需的固定握距。
- 重做后60帧中腕目标最大误差小于0.001米，脚踝目标误差小于0.001米；详细数值见[blender_verification.json](blender_verification.json)。这些是IK目标误差，不是完整手掌包柄或脚底碰撞的证明。
- **重新打开已保存工程验证编辑**：在第21帧将 `CTRL_Left_grip` 局部横移0.03米，手部实际移动约0.0300003米，目标误差约0.0000099米。随后复原，没有把测试修改保存回工程。见[editability_check.json](editability_check.json)。
- 逐帧看关键姿势、完整导出60帧；两版视频为512×512、20fps、3秒。GIF使用相同输出图像。
- Computer Use在Chrome打开对照，实际验证两视频加载/播放、滑条到第2帧、重置和0.5倍播放。预览默认单次播放，原始动作结尾不伪装无缝循环。

现有不足：中性人偶无角色造型，脚部网格简化、缺少手指包柄，挥击没有目标接触/受击反馈，身体发力仍需审片；锤子可能经过人体或地面，未建立碰撞。IK成立不代表表演或商业品质通过。

## 怎样打开并改一个地方

1. 用Blender打开 `hammer_lesson.blend`。文件保存于第21帧，显示重做版。按数字键盘0进入相机视图，空格播放。
2. 在Outliner搜索 `CTRL_Hammer_rigid`，选择后移动/旋转，双手通过子级目标和IK跟随。帧上修改需在对应Location/Rotation插入关键帧，才会保留到播放中。
3. 修改蓄力与击出速度：在Dope Sheet / Graph Editor调整该控制器第21、25、28、31帧；身体关键帧同步审查，不能只把锤移动到手够不到的位置。
4. 肘部不自然时选 `CTRL_Left_elbow` / `CTRL_Right_elbow` 调整pole位置，再检查整段。脚部控制器为 `CTRL_Left_foot` / `CTRL_Right_foot`。
5. 原始骨架 `A_MoMask_unedited` 和原动作仍在工程中，显示隐藏由Outliner控制。重做源脚本可重新渲染两版。

工程为密集原动作与自建控制器练习，未声称是完整Rigify角色或已重定向到日鹤。

## 重现

无需本地MoMask权重。输入BVH已经保留；重新生成AI结果有随机性，制作重现以这些本地文件为准。

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python docs/motion/tutorial-probe-2026-09-21/blender_lesson.py -- all
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python docs/motion/tutorial-probe-2026-09-21/verify_editability.py
```

`blender_lesson.py`覆盖本实验的工程、渲染帧与验证记录，不操作用户当前GUI中的未保存场景。`make_comparison.py`将已编码预览嵌入离线网页。教程和BVH来源记录随目录保存；原模型代码许可不自动覆盖所有权重/数据/产物商业授权，本次输出仅用于制作研究。
