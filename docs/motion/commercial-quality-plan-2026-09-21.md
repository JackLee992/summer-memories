# 从动作实验到商业品质：制作决策与样片任务书

2026-09-21。此文是调研结论与可执行任务书，不代表质量已达标，也不恢复暂停的游戏开发。商业画面水准与商业发行权利是两件事：当前《夏日重现》角色仍按同人原型范围使用；正式商业发布需取得相应授权或完成原创设计替换。

## 最重要的判断

当前 GIF 处于**运动技术预演**阶段，不是待加几层细节的成品动画。我们已证明固定骨长、双手握点、武器长度与跟随可以计算，但尚未建立专业角色原画、动作表演、清稿和游戏反馈。继续在几何人偶上增加弹簧、顶点和帧数，不能跨过这些工序。

推荐先追求“一个可重复生产的商业质量动作样本”，不以全游戏对标大片作为下一次验收目标。最适合当前成本约束的路线是：

**审定角色设计 → 专业关键姿势与线拍 → 分层骨骼复用＋关键部位替换绘画 → 清稿/上色 → 实际尺寸审片 → 游戏时序联调。**

这是一项项目判断，不是对任何工具的一键效果承诺。最需要投入的稀缺能力是角色动作原画与审片能力；角色设计、动画师、技术美术是职责，不意味着必须招聘三个全职岗位。

## 我们的差距在哪里

| 层次 | 现有证据 | 达到目标还缺什么 |
|---|---|---|
| 造型 | 几何头脸、简化衣发和武器 | 明确的头身比、脸部与发束形体、肩肘膝结构、服装材质、游戏尺寸下的剪影；不是给现有几何线条加高清纹理 |
| 姿势 | 肢体长度稳定、双手握点固定 | 身体与重物的关系、肩胯对抗、支撑腿承重、手腕朝向、负空间；IK 只解位置，不能决定漂亮姿势 |
| 表演 | 有预备、击出、停顿、恢复 | 发力顺序与目的、锤头滞后、卸力、转面与遮挡；按相同侧面形体旋转仍显纸片 |
| 二级运动 | 发束阻尼和避让可运行 | 发束体积、穿插和清晰轮廓；上一轮65帧中61帧触发避让，表明结构设计仍需改，不是“物理参数已完成” |
| 成片 | 白底粗图可循环 | 清线、色板、替换手脸、透明边缘、背景对比、接触阴影和恰当特效 |
| 游戏体验 | 本轮没有运行时验证 | 输入响应、攻击判定、命中/挥空差异、受击、取消、切人和回溯恢复；GIF不能证明这些成立 |

## 游戏与动画需要分别交付

商业短片可以针对固定镜头定制姿势、透视和剪辑；商业游戏动作必须在约定输入与状态分支中成立。两者不应以“都输出视频”混为一谈。

- **短片样本**：一个约3秒、有明确目标点的挥锤镜头，审构图、表演、线条、颜色与合成。镜头固定是本样片约束，不表示所有商业动画都固定镜头。
- **游戏样本**：同一动作支持待机/移动进入、挥空与命中、恢复以及允许的取消；需要受击目标与音画反馈。样片展示3秒不等于玩家锁定3秒。正常攻击节奏应由玩法确定，不能沿用现有2.6秒GIF作为战斗配置。

“60fps”也要区分画面刷新、模拟更新和独立原画曝光次数。风格化动画可以有选择地停帧、两格一画和快段一格一画；把所有段都平滑到60张新图可能削弱力量感。具体节奏需要线拍审定，不设行业通用攻击帧数。

## 工具选择：先选可交付的制作方法

### 优先：2D骨骼＋网格＋替换原画

角色画成完整分层资产；普通待机和移动复用骨架。扛肩、最大蓄力、击出、手掌转面、极端肘弯、头发交叉等使用替换绘画或局部逐帧层。脸和手不是同一张图随便拉伸就能转面的。

- **有成熟动画师且接受软件成本**：Spine Professional 是有官方Unity runtime的候选；官方IK、物理约束、网格和attachment key支持所需机制，但不自动生成表演。Essential不包含IK和物理约束，不能用低档版本价格代表本方案成本。
- **希望先控制工具成本**：Krita/OpenToonz/Blender 做离线手绘与混合动画，再输出透明序列；本机已有Blender可复用。它们的可用性不等于“没有人工成本”，也不保证每种rig能原样导入Unity。
- 不建议现在同时接入多个角色runtime。Spine在GitHub提供runtime源码，但不是任意用途MIT依赖；正式集成按其Editor/Runtime许可核查。本轮未购买、未安装、未修改Unity依赖。

### 次选：3D支架→固定视角渲染→2D修形

当存在大量持武器动作、换装、多视角需求，或能复用成熟可动画角色时值得比较。必须算上拓扑、绑定、权重、动作清理、卡通渲染和二维修形工时。一个从图像生成的粘连网格，不等于省掉了这些工序。游戏引擎继续Unity6横版2D，不需要恢复自由3D玩法。

### AI的位置

MoMask/Kimodo/GEM-X可提供动作候选和参考；ToonCrafter只在批准的相邻关键姿势间做有限补画试验；Wan Animate可探索外观表现。它们都不能承担“正确双手抓握＋角色不走形＋游戏取消时序”的最终签核。

AI仍有价值，但要按**可采用结果的总制作工时**评价，而非一段生成视频的等待时间。当前没有本项目证据支持“一人加模型即可稳定达到商业成片”的承诺。

## 可直接执行的日鹤挥锤样片任务书

### 范围与设计约束

- 一名角色、一把长柄锤、固定最终游戏侧视机位；不加第二技能、换装或多角色。
- 扛肩姿势是识别点。锤头保持适中体积，柄长根据审定角色标准图固定；不以每次生成画面的偶然比例为准。
- 一个攻击意图：从扛肩预备，明确向前方目标挥击，卸力后回到可继续行动的姿势。目标位置先确定，不能先摆动画再猜打中了哪里。
- 第一次只做灰阶角色和简单目标。音效、震屏、粒子关闭仍应能看懂动作。背景使用最终画面截图作尺寸/对比参考，不恢复关卡制作。

### 分阶段交付及停止条件

| 阶段 | 要交什么 | 通过后才进入下一阶段 |
|---|---|---|
| 1 造型 | 最终机位标准图、需要的转面、武器正侧图与握点；标明游戏显示尺寸 | 美术审型、用户审风格；单帧本身还不好看就退回设计，不先绑骨 |
| 2 原画 | 建议5–8个关键姿势：扛肩、预备/蓄力、击出转折、接触、卸力、恢复；数量按动作需要 | 剪影能读懂，身体参与发力，锤头与双手不互相遮死。这里的5–8不是行业固定张数 |
| 3 线拍 | 带帧号、曝光表的粗动画；明确中间转折，不只是端点补间 | 正常速度有重量和节奏；慢放无结构突变。连续两轮仍不成立，回到原画而非加特效 |
| 4 混合制作 | 分层rig或逐帧工程；必要的替换手、脸、躯干和发束画 | 普通段复用，极端段可改；锤长/握点稳定、遮挡正确，无明显皮筋式变形 |
| 5 清稿与合成 | 无特效版、完成版；灰底和游戏背景两种预览 | 游戏实际大小仍好读；线宽/色块/透明边缘一致，效果不遮丑 |
| 6 游戏交付 | 动作源、透明图集或选定runtime资产、pivot、事件表、已知限制 | 未来在恢复开发后验证命中/挥空/取消/切人/回溯；本轮不执行构建 |

至少保留原生工程、分层原画、替换图、曝光表、导出设置和版本记录。只交一个MP4不满足游戏资产可维护性要求。

## 本项目额外容易遗漏的商业门槛

1. **命中与挥空**：接触姿势可设计，但hitstop只能按实际命中规则触发；不能把GIF里的硬停顿无条件用于每次挥空。
2. **切人和手表变形**：转换时角色的朝向、位置、动作阶段和目标状态要有清楚交接，不是两段视频淡入淡出。
3. **回溯与发束物理**：Spine官方文档区分编辑器Deterministic预览与运行时状态；编辑器可倒拖不证明游戏回溯正确。后续需选取“装饰动态重置”“保存/恢复物理状态”或“从确定起点重演”等策略，并验证成本。攻击判定不能依赖未控制的装饰性头发摆动。
4. **画面转向**：镜像是否允许、左右握锤是否换手、不对称服装如何处理，要在源资产阶段决定。
5. **批量生产**：同一动画师能否快速改锤长、时间、手部姿势，并稳定再导出，比一次幸运生成更重要。

## 成本怎样真实估，而不是拍脑袋

先向候选制作者发同一任务书，要求拆分：设计/原画、线拍、绑定与替换图、清稿合成、技术交付，以及包含几轮修改。先完成一个付费或自制样片，再据实估动作库；本轮没有联系任何外部人员或产生付费。

记录：

`可交付成本 = 设计与原画 + 绑定/中间画 + 清稿合成 + 返修 + 集成验证 + 工具/计算成本`

比较的是同一质量门槛下的时间，不将失败生成排除在统计外。角色首个动作含固定搭建成本；后续动作有复用收益，但高难度转身/武器交互不能按普通待机等价计价。此处不给未经报价与试样验证的金额、日产量或“节省百分比”。

如果暂时没有熟练的角色动作绘制/审核者，建议保持低成本预演目标；要追求商业观感，优先把有限预算用于审定角色与关键原画。继续编写几何动画程序不能替代这项技能。
