# 商业 2D 动画工序与单动作质量门槛研究

日期：2026-09-21。范围：横版 2D 单角色动作的制作方法研究；未生成素材、下载模型、修改玩法或启动构建。本文的“商业水准”指可验收的画面与交互制作质量，不代表原作角色获得商业使用授权。现行素材来源与商业化重绘约束继续适用。

## 结论

商业质感不是“更多中间帧”或“骨架更复杂”。它来自统一角色设计、动作设计、时序设计、逐帧修形，以及在最终显示尺寸下的审核。可以复用骨骼、贴图和动作库，但不能跳过关键姿势和形体审核。独立生成漂亮图片再插帧，不会自动得到同一角色连续表演：插帧只处理给定端点之间的过渡，无法代替对重心、受力、转面、遮挡和表演意图的决定。

对当前项目，优先建议：**人工审定的侧面角色模型表 + 少量高质量关键姿势 + 骨骼驱动普通过渡 + 转面/极限动作的替换绘画 + 手绘头发与冲击修饰**。先把一个 3 秒动作做到可信，再评估批量生产。该建议是基于下列官方工具机制的项目判断，不是对某商业作品幕后工艺的未经证实归因。

## 一手资料支持了什么

本次实际读取 6 个核心页面；OpenToonz 文档站受访问限制，改读其官方组织文档仓库的原始源文件。没有将未能读取的 Toon Boom 或 Blender Studio 页面当作证据。

1. [Krita：Animation with Krita](https://docs.krita.org/en/user_manual/animation.html)：先重要姿势，再中间帧；脚本/分镜/animatic 规划；洋葱皮；脚接触地面时逐帧固定落点。还明确提醒中间画本身涉及动画师风格，非简单工具操作。支持“先线拍与时序，再精画”，不支持“固定帧率即可达商业质量”。
2. [OpenToonz：Production Workflow（官方文档源码）](https://github.com/opentoonz/opentoonz_docs/blob/master/source/production_workflow.rst)：设计、分镜、animatic、素材库、layout、animation、特效、render；角色库包含正背侧与三分之四视图；设计要考虑隐藏关节；调色板与绘画关联；合成统一时序与效果。支持制作分工与阶段验收。
3. [OpenToonz：Creating Cutout Animation（官方文档源码）](https://github.com/opentoonz/opentoonz_docs/blob/master/source/creating_cutout_animation.rst)：拆分角色、父子层级、pivot、IK；部件可以是含多幅绘画的 animation level；hooks 可逐画定义连接位置，避免躯干换画后肢体连接失效。直接支持“骨骼变换 + 替换绘画”混合方法。
4. [OpenToonz：Cleaning-up Scanned Drawings（官方文档源码）](https://github.com/opentoonz/opentoonz_docs/blob/master/source/cleaning-up_scanned_drawings.rst)：扫描稿定位、轮廓识别、裁切、线条和抗锯齿处理。注意：这里的自动 cleanup 是扫描处理，**不是**会替人修正人体结构的动画清稿师；文档还标注部分 Autoadjust 功能不可用。
5. [Blender：Grease Pencil Animation Introduction](https://docs.blender.org/manual/en/latest/grease_pencil/animation/introduction.html)：同一工具支持整物体变换、逐帧绘画、点变形与父级/骨架继承；提供洋葱皮和多帧编辑。支持混合作业的可行性，不代表可直接导出为 Unity 中可用的同构运行时骨架。
6. [Blender：Grease Pencil Interpolation](https://docs.blender.org/manual/en/latest/grease_pencil/animation/interpolation.html)：明确以 simple shapes 描述自动生成 breakdown 的用途，提供步长、笔画翻转、平滑等控制。它是几何插值，不是已证明理解角色表演的生成式 AI。

## 从设计到交付的工序

| 工序 | 真正需要决定的事 | 人工审核点 | 不能用什么来替代 |
|---|---|---|---|
| 模型表与色模 | 头身比、侧/三分之四转面、面部特征、发束体积、服装结构、线宽和色板 | 角色设计者统一正侧视；画出抬臂、屈膝、转头时关节如何变化 | 一张高精度立绘 |
| Pose design | 动作意图、动作线、负空间、视线、肩胯对抗、接触关系 | 动画师画能单独读懂的预备、极限、接触、恢复姿势；黑色剪影审核 | 随机挑视频帧或只调关节角度 |
| Layout | 摄像机、地平线、角色尺寸、站立基线、运动范围、道具位置 | 在实际游戏画幅中判断手脚和头发是否可辨；明确世界位移归属 | 单独白底大图 |
| 关键帧与 breakdown | 哪个部位先动、从哪条弧线通过、何时转面与换遮挡、受力如何传递 | 动画师控制中间的结构转折；转面处补画而非把侧脸拉宽 | 两个端点之间均匀插值 |
| Timing / spacing | 预备多久、加速多快、冲击停多久、恢复怎样衰减 | 先做低成本线拍；正常速度看重量感，再慢放查问题 | 一律 24/60 fps、“越流畅越好” |
| 中间画与二级运动 | 按批准的轨迹补画；发梢、衣摆相对躯干延迟与回弹 | 查体积、弧线、脚锁定、穿插；夸张形变须有前后逻辑 | 无约束的全身噪声摆动 |
| Cleanup 与上色 | 保留姿势力度，统一结构、线条、色块、边缘 | 人工纠正不合模型的头脸手；控制有意线条活性与无意抖动 | 把所有线条滤得很平或自动扫描清理 |
| 合成与输出 | 前后层级、遮挡、接触阴影、局部特效、透明边缘、色彩 | 灰底与最终背景双检；关闭特效仍应读懂动作 | 用辉光、抖屏、模糊掩盖错误 |

“关键帧”需区分：绘画关键姿势是表演决策，软件变换关键帧只是参数记录；增加后者数量不会自动得到前者质量。

## 混合骨骼与替换绘画怎样落地

普通待机、呼吸、轻微摆臂、常规循环适合骨骼复用。头部转面、手掌朝向变化、脚掌着地、肩肘极限弯折、头发甩动交叉和极端透视，应准备替换画或局部逐帧层。单个“侧面”肢体旋转不能凭空生成肢体的另一面。

每个需要换画的部件要有稳定命名、接缝余量、pivot/连接点、前后遮挡规则；换画不只是换贴图，还需检查连接位置与轮廓跳变。OpenToonz 的 hooks 机制就是对此类问题的明确工具支持 [3]。如果运行时不支持同等机制，应先评估烘焙帧序列，不能假定软件里的 rig 自动兼容 Unity。

头发先作为几个有明确体积的大束设计，再给根部跟随、主束延迟、发梢衰减；不要用很多细线自由抖动冒充质量。用于能力攻击的发束必须另设计发力和命中轨迹，不能直接套用装饰性摆动。

## 商业短片镜头与可交互游戏动作不同

| 要求 | 短片/过场镜头 | 可交互游戏动作 |
|---|---|---|
| 时间与镜头 | 固定时长与相机，可以为一帧构图特制 | 任意开始、打断、转向、速度与背景；需明确定义支持范围 |
| 完成标准 | 镜头在剪辑、声音与合成中成立 | 与 idle/run/hit 等状态连接；输入到动作反馈及时，不能只靠独立视频好看 |
| 位移 | 镜头内运动正确即可 | 动画位移与角色控制器只能有清楚的主从关系，避免双重移动与滑步 |
| 接触/事件 | 视觉同步为主 | 脚接地、攻击命中、受击窗口、音效、取消窗口要绑定明确时间点 |
| 循环/回溯 | 可用剪辑隐藏接缝 | 循环无首尾跳；切入切出可控；反向播放不自动等于物理合理的回溯表演 |
| 交付 | 合成镜头与编辑工程 | 可编辑动作源、透明资源、尺寸/pivot、时序和事件规范、状态连接说明 |

下述 3 秒是一个验证片段，不规定玩家必须锁定操作 3 秒。若示范包含等待和展示，应与实际动作/恢复时间分开。

## 一个角色、一个 3 秒动作的质量 gates

建议样本：固定侧视“蓄力 → 一次头发甩击 → 收回站稳”，只有一个清晰目标点。背景用简单基线，避免镜头移动和大量特效。先不制作多角色和完整连招。

以下门槛是**本项目建议验收规范**，不是资料中声称的行业统一标准；每一关未过，不进入昂贵的清稿/批量出图。

| Gate | 交付和审核方式 | 通过条件 | 必须介入的人 |
|---|---|---|---|
| G0 设计锁定 | 一页模型表、色板、输出尺寸/角色屏幕高度、动作说明 | 同一侧面与转面可认作同一角色；指定参考来源；角色细节在游戏实际大小仍可读 | 角色设计/美术负责人 |
| G1 姿势锁定 | 约 5–8 张粗关键姿势；按意图决定数量 | 隐去头发特效仍读懂预备/发力/恢复；支撑脚、躯干和重心关系可信；无关键解剖错误 | 动画师；负责人审姿势 |
| G2 线拍锁时 | 带帧号、基线的 3 秒粗线拍；曝光表 | 正常速度能读出快慢、重量和命中点；0.25 倍看弧线不折返；时序没有为补帧而均分 | 动画师决定 timing/breakdown |
| G3 连续性锁定 | 粗中间画或 rig + 替换画；洋葱皮/叠图 | 支撑段脚底无可见滑动；头脸/手/衣服无无意换型；换画不脱节；头发的遮挡顺序正确 | 动画师逐帧修形、绑定师修连接 |
| G4 清稿上色 | 分层源文件、统一色板 | 无漏色/闪色、随机线宽与透明边缘污染；在目标尺寸和 200% 下均审核；保留动作力度 | 清稿/上色人员；美术审型 |
| G5 合成验收 | 无特效版 + 最终版并列，灰底/游戏背景预览 | 特效强化但不遮掉读招；脚有接触感；头发命中位置准确；不存在靠模糊遮丑 | 合成/特效；动画负责人 |
| G6 游戏交付验收 | 导入后录屏及事件表；当前仅规定未来检查，不启动构建 | 与待机连接、左右向、允许打断点、重播一致；命中和画面同步；资源尺寸/pivot 无漂移 | 技术美术/程序与动画师联合 |

时序示例可以采用 24 fps 的 72 个时间格，常规段按两格一画、冲击段按一格一画、部分姿势停留；**72 格不等于必须画 72 张，也不等于游戏必须以 24 fps 更新**。具体张数随动作修订，不能提前用固定“AI 一键出 36 帧”作为通过条件。

每次 review 只记录具体帧号、问题、负责人和修改结果。对同一缺陷连续两轮修不动，应回退到姿势/结构设计，而非继续加中间帧或后期效果。

## AI 能帮到哪里、不能据此保证什么

- **可尝试的辅助**：动作与构图参考候选、模型表草案、局部清理/分割草案、背景或色彩探索、经人工指定端点和中间约束后的候选补画。每个用途都必须用当前角色试样衡量净节省工时；这些是建议的实验方向，本次没有对模型成功率做实测。
- **可自动化且不必用生成式 AI**：文件命名、尺寸/alpha/帧数检查、导出、接触点轨迹标记、重复帧和明显跳变提示。算法检查不能判定表演是否动人。
- **不可直接交给模型担保**：角色全程一致、准确的发力链、手脸结构、遮挡拓扑、命中/取消时间、版权来源、最终艺术签核。自动补间不是新姿势设计，视频生成也不是可编辑 rig。
- **明确区分**：IK、几何插值、洋葱皮、骨骼曲线是确定性的制作工具，不应统称为“大模型能力”。现有官方资料支持这些制作工具的工作方式，不证明大模型能替代完整商业制作链。

最重要的人工投入在 G0–G3：设计者画稳定角色，动画师决定姿势和节奏，必要处重画。若只能由代理调参数而没有可靠绘画修正能力，应把目标诚实限定为动作草稿/参考，而不能宣称已经达到商业成片。

## 应留下的交付文件

一次动作精修的最小可复用包应包含：

- `model-sheet.png`、`palette`、`design-notes.md`：视图、色板、身高比例、允许/禁止形变和素材来源。
- `action-brief.md`、`keyposes.png`、`exposure-sheet.csv`：意图、关键姿势编号、帧号/持续时间、接触/命中/恢复/允许打断事件。
- 原生可编辑工程：按选定软件保留 `.kra`、OpenToonz 场景与完整 levels/palettes，或 `.blend`；不能只交 MP4。rig、替换画、头发、特效保持能分开修改。
- `rough-line-test.mp4`、`clean-no-fx.mp4`、`final-preview.mp4`：同一帧率和时序，可回看制作判断。
- 透明 PNG 序列或商定的 runtime 资产；统一画布、pivot、像素比例、命名、颜色/alpha 规范；图集如有裁切须保留偏移数据。
- `review-log.md`、`export-manifest`：版本、使用软件版本、导出设置、事件时间、已通过 gates、遗留问题和工具/AI 使用记录。

以上是计划中的文件契约，本次没有伪造这些制作交付件。下一步若获准做试样，应先审 G0/G1，而不是同时铺开角色库、权重下载与整套游戏动作。
